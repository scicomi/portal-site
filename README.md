# SciComi Portal — サイエンスコミュニケーター ポータルサイト

東海大学サイエンスコミュニケーターのイベント管理ポータル。

**公開URL**: https://scicomi.github.io/portal-site/

> **2026年9月に、バックエンドを Google Apps Script(GAS)+スプレッドシートから Cloudflare(Workers + D1 + R2)へ移行した。**
> 移行前の GAS は同期エラー・ログイン画面の頻発が続いていたため(Google 側の入口が不安定で、コードでは直せなかった)。
> 経緯と設計は [docs/08_cloudflare_migration_design.md](docs/08_cloudflare_migration_design.md)、バックエンドの手順は [worker/README.md](worker/README.md)。

> **担当を引き継ぐ人は [人への引き継ぎ.md](人への引き継ぎ.md) を読むこと。AI に作業を頼むときは、最初に [AI向けREADME.md](AI向けREADME.md) を読ませること。**

## システム構成

```
┌───────────────────┐    ┌───────────────────────┐    ┌──────────────────┐
│  GitHub Pages     │ ⇄  │  Cloudflare Workers   │ ⇄  │  D1  (データ)     │
│  (フロントエンド)  │    │  (API)  worker/       │    │  R2  (ファイル・  │
│  HTML/CSS/JS      │    │                       │    │      バックアップ) │
└───────────────────┘    └───────────────────────┘    └──────────────────┘
        ↑
   メンバーがアクセス
```

| レイヤー | サービス | 役割 |
|---|---|---|
| **フロントエンド** | GitHub Pages | 静的HTML/CSS/JSを配信。無料 |
| **バックエンドAPI** | Cloudflare Workers(`worker/`) | 認証・データの読み書き・Gemini・LINE通知・定期バックアップ |
| **データベース** | Cloudflare D1(SQLite) | イベント・メンバー・実験・投票・設定・監査ログ |
| **ファイル** | Cloudflare R2 | アップロードされた画像・資料、毎日のバックアップ |

API のURL: `https://scicomi-portal.scicomi.workers.dev`(`config.js` の `API_URL`)

### 費用

いずれも無料枠で運用できる規模(メンバー約30人)。

| | 無料枠 |
|---|---|
| Workers | 1日10万リクエスト、1回のCPU時間10ms |
| D1 | 5GB、読み取り500万行/日、書き込み10万行/日 |
| R2 | 10GB(ダウンロード転送は無料) |

超えると D1 はエラーを返すようになる(課金ではなく停止)。増えてきたら有料プラン(月 $5〜)に上げる。Cloudflare ダッシュボードの「Workers & Pages → scicomi-portal」で使用量を確認できる。

(D1 は文字のデータを入れるデータベース、R2 は写真や資料などのファイルを置くストレージ)

## ページ構成

9ページ構成(誰でも使う7ページ＋管理者専用の2ページ)：

| ページ | URL | 役割 |
|---|---|---|
| ホーム | `index.html` | ダッシュボード。許可願/報告書の期限・振り返り未記入・出欠一括回答・直近イベント |
| イベント | `events.html` | 日程一覧（カレンダー）＋クイック作成・編集・削除 |
| イベント別 | `event-series.html` | **イベント1件の正規詳細ページ**。パラメータ無しなら全シリーズの一覧。`?event=<ID>` で該当回の詳細（現地情報・書類ステータス・参加状況・振り返り・統計） |
| メンバー | `members.html` | 3カテゴリ（アドバイザー/コーディネーター/メンバー）テーブル表示 |
| 実験ネタ | `experiments.html` | フィルタ式（工作/実験ショー/その他）の実験データベース |
| 実験の詳細 | `experiment-detail.html` | `?id=<ID>` で実験1件の詳細（使用物品・手順・写真・動画・振り返り）。実験ネタ一覧の各行から開く |
| AI検索 | `bot.html` | Gemini による自然文検索・要約（キー未設定でもキーワード検索は動く） |
| パスワード一覧 | `passwords.html` | 管理者専用 |
| 設定 | `settings.html` | 管理者専用 |

### イベント登録の2段階運用

1. **枠だけクイック作成**: 「＋」→ カテゴリ選択 → 名前と日付だけ入れて「作成」。
2. **あとから追記**: 作成後は自動でイベント詳細ページへ移動し、未入力項目（場所・時間・実験・担当など）がチェックリスト表示される。「編集」からいつでも追記できる。

開催日が決まった時点ですぐ登録し、詳細は決まり次第埋めていく運用を想定している。

├── worker/            # ★バックエンド（Cloudflare Workers）
│   ├── src/           #   API本体
│   ├── migrations/    #   D1 のテーブル定義（SQL）
│   ├── scripts/       #   パスワード設定・データ取り込み・突き合わせ・マージ・復元
│   ├── test/          #   結合テスト

├── .github/workflows/deploy-gas.yml   # 旧 GAS 用の自動デプロイ。不要になったら削除してよい

> **スクリプトの読み込み順**は全ページ共通で
> `config.js → api.js → app.js → 各ページ.js`。
> config.js が他の全てより先に読まれる前提なので、この順序は変えないこと。

### 拡張するときはまず config.js

カテゴリ追加・色変更・URL変更・期限ルール変更は、原則 **config.js だけ** 直せば全ページに反映される設計です。

| やりたいこと | config.js の該当箇所 |
|---|---|
| APIのURLを変えた | `API_URL` |
| イベント種類を増やす | `EVENT_CATEGORIES` に1行 |
| 実験タブを増やす | `EXPERIMENT_CATEGORIES` に1行 |
| メンバー区分を増やす | `MEMBER_CATEGORIES` に1行 |
| 書類期限の日数を変える | `DEADLINE_RULES`（設定ページからも変更可） |
| 期限警告の色しきい値 | `DEADLINE_ALERT` |

## 開発・編集方法

### フロントエンド（HTML/JS/CSS）を編集する場合

1. ファイルを編集する
2. ローカルで確認: `npx http-server . -p 8080 -c-1` を実行し、`http://localhost:8080` を開く
3. GitHub にアップロードすると GitHub Pages に反映される
   - `worker/` 内の **`node_modules/` `.wrangler/` `.dev.vars` は GitHub にアップロードしない**(`.gitignore` で除外済み。秘密の設定や大量の依存ファイルが入っている。無くても `npm install` などで作り直せる)。それ以外の `worker/` の中身はコードなのでアップロードしてよい

### バックエンド（API）を編集する場合

`worker/` を編集し、テストしてからデプロイする。詳しくは [worker/README.md](worker/README.md)。

```bash
cd worker
npm run dev      # ローカルで起動
npm test         # 結合テスト（別ターミナルで。API の契約を検証する）
npm run deploy   # 本番へ反映
```

### 本番に影響させずに試す

`index.html?api=http://127.0.0.1:8787`（ローカルの Worker）のように `?api=` を付けて開くと、そのブラウザだけ接続先を切り替えられる（`?api=reset` で解除）。`workers.dev` と `localhost` 以外は受け付けない。

## 運用・保守

### パスワード

> パスワードは**ハッシュ化**して D1 に保存される。設定画面には「設定済み／未設定」だけが表示され、現在の値は誰にも読み出せない。
> 設定画面が使えない緊急時は、`cd worker && node scripts/set-password.mjs member --remote`（幹部は `admin`）で設定できる（入力は伏せ字）。

### ログイン

ログインは 180 日間有効。パスワードの入力を繰り返し間違えると、その接続元からの試行は徐々に遅くなり、一定回数を超えると一時的に拒否される（10 分で解除）。

### API キー・トークンを設定したい

Gemini の API キーと LINE のチャネルアクセストークンは、設定ページから入力する。D1 に保存され、画面や API では「設定済み／未設定」しか返らない。

### パスワード一覧ページ（管理者専用）

 **URL・ログインID・パスワード** を管理者だけが閲覧・追加・編集・削除できるページ。

- ナビの「パスワード一覧」は**管理者ログイン時のみ表示**される（メンバーには見えない）。
- **閲覧・編集とも管理者トークン必須**（API 側でもガード。メンバー向けの一括取得 `listAll` には含めない）。
- ⚠ **セキュリティ注意**：第三者サービスのパスワードが**平文**で D1 に保存され、毎日のバックアップ(R2)にも含まれる。Cloudflare アカウントの管理者を幹部のみに限定し、画面共有・スクショの取り扱いに注意すること。より厳密に運用したい場合は専用パスワードマネージャ（Bitwarden 等）の利用も検討。

### データを直接見たい・直したい


- Cloudflare ダッシュボード → Storage & Databases → D1 → `scicomi-portal` → Console で SQL を実行できる。
- 更新するときは、必ず先にバックアップを取り、`WHERE ID = '...'` で対象を絞ること。
- `PartsList` / `Files` / `PrAssignments`：JSON文字列。形式を壊さないこと。
- `ID`：絶対に変更しない。`UpdatedAt` を手で書き換えると、編集中の人の競合検知が誤動作する。

### データをエクスポートしたい

- 毎日のバックアップ（下記）の JSON をダウンロードするのが一番簡単。
- コマンドで取り出す場合: `cd worker && npx wrangler d1 execute scicomi-portal --remote --json --command "SELECT * FROM events"`

### バックアップと復元

**毎日 03:00（日本時間）に、D1 の全データが R2 の `backups/YYYY-MM-DD.json` に自動保存される。**
- 世代数は設定の `backup_keep_count`（既定14）。古いものは自動で削除される。
- パスワードのハッシュ・API キーはバックアップに**含まれない**。
- R2 のファイル本体（アップロードされた画像・資料）はバックアップの対象外。R2 側に残っていればそのまま使える。

**復元する手順**（現在のデータは上書きされる）：

1. Cloudflare ダッシュボード → R2 → `scicomi-portal-files` → `backups/` から、戻したい日の JSON をダウンロードして `worker/` に置く
2. 予行（内容の表示だけ）: `cd worker && node scripts/restore.mjs <ファイル名> --remote`
3. 実行: `node scripts/restore.mjs <ファイル名> --remote --yes`

### 操作履歴を確認したい（監査ログ）

D1 の `audit_log` テーブルに、作成・更新・削除・ファイル操作・設定変更・ログイン失敗などが時系列で記録される。ダッシュボードの D1 Console で確認できる。
例: `SELECT Timestamp, Action, Detail, Role FROM audit_log ORDER BY Id DESC LIMIT 50;`
- 共通パスワード運用のため「誰が」までは特定できない（トークンのハッシュとロールのみ）
- 設定の `audit_keep_days`（既定365日）を超えた古い行は毎日自動で削除される

### 同時編集について

2人が同じイベント/メンバー/実験を同時に編集して保存すると、**後から保存した側が「他の人が編集しました」と表示され、最新内容が再読込される**（上書き事故を防ぐ楽観的競合検知）。再度編集して保存し直せばOK。

### 出欠の締切

出欠の回答は、イベントの「出欠締切」（未設定ならイベント最終日）の23:59まで。締切後は管理者だけが変更できる。

### ファイルのアップロード

イベントの資料や実験の写真をアップロードできる（1ファイル 10MB まで。上限はサーバーの設定 `file_max_mb` が正で、フロントも公開設定から同じ値を読んで事前チェックする。取得できないときは `config.js` の `FILE_UPLOAD.maxSizeMB`）。

- 保存先は R2。**閲覧にログインは不要**で、推測されにくいランダムな URL（`/files/<キー>`）で公開される。URL を知っている人は誰でも見られるので、個人情報を含むファイルはアップロードしないこと。
- 画像・PDF・動画・音声・テキスト以外（HTML など）は、ブラウザ内で開かずダウンロード扱いになる。
- 削除は管理者のみ。

## トラブルシューティング

### ログイン画面が繰り返し出る・「セッションの有効期限が切れました」

- パスワードを変更した直後は、全員がログインし直しになる（仕様）。
- 一部の人だけ続く場合は、その人のブラウザで F12 → Console に `api.errorLogText()` と入力して出力を確認する（直近30件の通信エラーが記録されている）。

### 「Failed to fetch」「サーバーからの応答を解釈できません」

1. `https://scicomi-portal.scicomi.workers.dev` に `{"action":"version"}` を POST して応答があるか確認（下記コマンド）。
2. 応答がなければ、[Cloudflare のステータス](https://www.cloudflarestatus.com/) と、ダッシュボードの Workers のログ（Observability / Logs）を確認。
3. 応答があるのに特定の端末だけ失敗するなら、その端末のネットワーク・拡張機能・ブラウザを疑う。

```bash
curl -X POST https://scicomi-portal.scicomi.workers.dev -d '{"action":"version"}'
```

### 保存しても反映されない・エラーになる

- 画面上部の同期ステータスにマウスを合わせると、エラーの内容が出る。
- Workers の無料枠（1日10万リクエスト、D1 の書き込み10万行/日）を超えると、D1 がエラーを返す。ダッシュボードで使用量を確認し、超えていたら有料プランに上げる。

### Bot（Gemini）が「レート制限／無料枠の上限」になる

APIキーを設定しても Bot が AI 回答にならず「キーワード検索に切り替えます」となる場合、ほとんどは **Gemini 無料枠の上限（429）** が原因。キー自体が無効なら別メッセージ（`APIキーが無効です`）になるので、429 = **キーは有効だが回数制限に当たっている**。

- 無料枠の上限は **APIキー単位ではなくプロジェクト単位**。このサイトは**1本のサーバー側キーを全メンバーで共有**するため、同時に数人が Bot を使うとすぐ「1分あたり」の上限に達する。
- 1日の上限はサイト全体で 1,500 回（Bot ページ上部のゲージで確認できる）。Google 側の1日上限は太平洋時間0時（日本時間 約17時）にリセットされる。
- **使用モデル**は設定ページの「使用モデル」で切り替えられる。モデルが廃止されて 404 になった場合は、サーバーが利用可能なモデルを自動検出して切り替える（コード変更不要）。既定は `gemini-2.5-flash-lite`。
- 「1分あたり」の 429 は自動で数十秒待って1回だけ再試行される。「1日あたり」は当日は回復しないので、キーワード検索に切り替わる。
- 頻発する場合は、Google AI Studio でキーの残量・無料枠を確認する。無料枠が出ない地域・アカウントなら、請求先を有効化すると上限が大幅に上がる。
- Bot は未設定でもキーワード検索で動く。

### 旧 GAS へ戻したい（緊急時のみ）

1. `config.js` の `API_URL` を旧 GAS のデプロイ URL に戻して再公開する
2. GAS の `Code.gs` の `READ_ONLY_MODE` を `false` にして、新しいバージョンでデプロイする
3. **新サーバーで入力されたデータは旧 GAS には入っていない**ので、戻すのは最後の手段にする

## 既知の制約・将来課題

- **個人認証なし**：共通パスワード方式のため、監査ログで「誰が」までは特定できない。個人ごとのログイン（メールのワンタイムコード、Cloudflare Access など）は将来検討。
- **メンバー・実験ネタの編集はサーバーでは幹部に限定していない**：一般パスワードでログインした人も、API を直接呼べば追加・編集できる（削除・パスワード一覧・設定は幹部のみ）。画面で編集前に幹部の認証を求める箇所は、誤操作を防ぐためのもの。
- **メンバーは1年度1行モデル**：複数年在籍や昇格（member→coordinator）の履歴は持てない。年度をまたぐ場合は各年度に行を作る運用。
- **実験の資料URLは1つ（`SlidesURL`）**：複数資料を持たせるには配列化が必要。
- **廃止した機能**：リマインダーメール、年間レポートのメール送信（2026-09 に廃止）。
- **管理者がスプレッドシートを直接編集する運用は終了**（データは D1）。画面から編集するか、D1 Console を使う。
- **PWA化・iCalエクスポート・通知の多様化・分析ダッシュボード**：いずれも独立した機能追加として将来検討。

### 考え方（要約）

- GitHub のコードには、パスワードや API キーを含めていない。**コードだけを手に入れても、サイトの更新もデータの閲覧もできない**
- 更新に必要な「鍵」は、人が引き継ぐ：**共有メール、Cloudflare アカウント（2段階認証含む）、GitHub Organization の Owner 権限、ポータルの幹部パスワード、支払いカード**
- コードの修正や手順の相談は AI に任せてよい。AI 向けの指示書は **[AI向けREADME.md](AI向けREADME.md)**（`CLAUDE.md` `AGENTS.md` はそこへの入口）
- 新任者は自分の PC で `cd worker && npm install` と `npx wrangler login`（本人がブラウザで許可）を行う。AI にパスワードや API キーを渡してはいけない

### よくある質問

**Q. 開発者が引退した後にバグが出たらどうする？**

A. 主な選択肢：
- 毎日のバックアップがあるので、データは失われない
- 知り合いのエンジニアに依頼する（このREADMEと `docs/08_cloudflare_migration_design.md`、`worker/README.md` を渡せば理解できる）
- 最悪、バックアップの JSON を表計算ソフトで見れば、情報は取り出せる

**Q. サイトをまるごと別の場所に移したい**

A. フロント（HTML/CSS/JS）は完全に静的なので、Netlify、Vercel、Cloudflare Pages など好きなホスティングに移せる。移した先のURLを、`worker/wrangler.toml` の `ALLOWED_ORIGINS` に追加して再デプロイすること（追加しないと、ブラウザが API を呼べない）。

**Q. データだけ取り出したい**

A. 上の「データをエクスポートしたい」を参照。
