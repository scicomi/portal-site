# 07. 参加投票の再設計 思案書 — vote.html は本当に必要か

> **実施記録（2026-07-08）**: 案A を実装済み。リンク未共有とのことでリダイレクタは置かず
> vote.html / vote.js は即削除した。§5.1・§5.2・§5.4 も実装済み（§5.3 は方針どおり現状維持）。
> 共通実装は `vote-widget.js`。バックエンドは `EventVotes` に `Note` 列、`Events` に
> `VoteDeadline` 列を追加、`listAll` が votes を同梱するようになった（要 GAS 再デプロイ +
> `setupSpreadsheet()` 再実行）。スキーマは docs/01 を参照。

**結論（先出し）**: vote.html は**廃止してよい**。投票機能そのものはホームの「出欠の回答」で既に
ページ内完結が実現できており、vote.html は「同じ機能の二重実装＋余計なページ遷移」になっている。
ただし LINE 等に貼られた旧リンク（`vote.html?id=...`）を割らないため、**数行のリダイレクタとして
一定期間残す**移行方式を推奨する（→ §4.3）。

## 1. 現状整理

### 1.1 投票データの保存方式

| 項目 | 内容 |
|---|---|
| 保存先 | Google スプレッドシートの `EventVotes` シート（gas/Code.gs:23） |
| 1行の形 | `eventId, memberId, status, updatedAt`（gas/Code.gs:1915） |
| 書き込み | `submitVote` アクションで (eventId, memberId) をキーに **upsert**（上書き。履歴は残らない） |
| 監査 | 投票のたびに `appendAuditLog('vote', ...)` が記録される（gas/Code.gs:411）→ 変更の追跡は一応可能 |
| status | `attend` / `absent` / `undecided` の3値のみ。サーバー側で検証あり（gas/Code.gs:407） |
| 本人性 | ログイン（サイト共通パスワード）＋プルダウンで名前を自己申告。選んだ名前は localStorage キー `scicomi_vote_member` に端末記憶（vote.js:8, home.js:14 で**同じキーを共有**） |
| 対象者 | コーディネーター・アドバイザーは対象外。イベント年度在籍かつ Active なメンバーのみ（vote.js:44-54） |
| 締切 | イベント最終日の 23:59 まで。過ぎると vote.html 側でボタンを無効化（vote.js:104-116） |

**注意**: docs/01_sheets_schema.md に `EventVotes` シートの記載が無い（スキーマ文書が投票機能に追随していない）。

### 1.2 投票UIの入口一覧 — 「どこに何が表示されているか」

現在、投票への入口は **4系統** あり、うち1つだけがページ内完結、残り3つは vote.html へ飛ぶ。

| # | ページ | 場所 | 表示条件 | 挙動 |
|---|---|---|---|---|
| 1 | **ホーム** (index.html:49-63) | 「出欠の回答」セクション。ヒーローの「出欠を回答」ボタンはここへのページ内アンカー（index.html:20） | 常時。名前を選ぶと直近10件の日程に 参加/不参加/未定 ボタンが出る | **ページ内で完結**（home.js:107-209、楽観的更新＋トースト。vote.html 不使用） |
| 2 | **日程一覧** (events.html) | 行内の「参加 n」バッジ（script.js:496） | 今後の日程 **かつ 回答が1件以上あるとき** | vote.html?id=... へ**遷移** |
| 3 | **日程一覧** | 行タップ → 概要ポップアップ内の「出欠を回答」ボタン（script.js:558） | 今後の日程のみ | vote.html へ**遷移** |
| 4 | **イベント詳細** (event-series.html) | 「参加状況」カードの「回答する」（event-series.js:622）と、「回答一覧」モーダル内の「回答する」（event-series.js:789） | 常時 | vote.html へ**遷移** |

vote.html 自体はナビゲーション（config.js:105-115 の NAV_ITEMS）に**含まれない**。
`?id=ev_xxx` 付きのリンクからしか到達できない「行き止まりページ」で、戻る手段は「日程一覧に戻る」ボタンのみ。

### 1.3 vote.html が持つ機能（vote.js 全329行）

- イベントヘッダー表示（タイトル・日時・場所・カテゴリバッジ）
- 名前選択（localStorage 記憶・「名前を変更」）
- 参加/不参加/未定 の3ボタン ＋ **確認ダイアログ**（showConfirmDialog）
- 現在の自分の回答と更新日時の表示
- 集計サマリー（参加/不参加/未定/**未回答** の4カウント）・「全員回答済み」表示
- 回答一覧の開閉（ステータス別の名前＋**回答日時**つき）
- 締切（最終日23:59）後のボタン無効化

## 2. 評価

### 2.1 問題点（UI/UX・運用・実装）

**(a) 導線が2つの世界観に分裂している。**
ホームでは「その場でポチッと回答」なのに、一覧・詳細からは「別ページに飛んで→名前を確認して→
ボタンを押して→確認ダイアログに答えて→戻る」。同じ操作の体験がページによって別物で、
ユーザーの指摘どおり導線として一貫性がなく見づらい。

**(b) イベント詳細ページで投票が完結しない。**
event-series の「参加状況」カードは集計サマリーと回答一覧（名前）まで表示するのに、
肝心の回答だけ別ページ。**情報を見る場所と操作する場所が分かれている**のは典型的なアンチパターン。

**(c) 最初の1票への導線が弱い。**
日程一覧の「参加 n」バッジは「回答が1件以上あるとき」しか出ない（script.js:493-497）。
つまり誰も回答していない日程ほど回答してほしいのに、一覧からは行タップ→ポップアップ経由でしか
投票に辿り着けない。

**(d) 操作の作法まで場所ごとに違う。**
ホームは楽観的更新で即送信（home.js:185-209）、vote.html は確認ダイアログを挟む（vote.js:193）。
「押したら即決まるのか、確認されるのか」がページによって異なり、学習コストになる。

**(e) 二重実装による保守コスト。**
名前選択＋記憶、スタッフ除外、年度絞り込み、集計……が vote.js / home.js / event-series.js の
**3ファイルにそれぞれ実装**されている（vote.js:44-56, home.js:102-113, event-series.js:676-692）。
仕様変更（例: 対象役職の変更）のたびに3か所直す必要があり、既に確認ダイアログの有無という差分が生まれている。

**(f) vote.html は重い。**
単一イベントの投票のために `api.listAll()`（全イベント・全メンバー・全実験）を取得している（vote.js:30-33）。

### 2.2 vote.html にしか無い価値（廃止時に失うもの）

| 価値 | 代替可能性 |
|---|---|
| **共有用の直リンク**（LINE 等に「ここから回答して」と貼れる、迷いのない1画面） | event-series.html?event=xxx への直リンク＋自動スクロールで代替可（→ §4.2）。ただし「投票以外の情報が多い画面に着地する」ことは受け入れる必要がある |
| 回答一覧の**日時つき**表示 | event-series の回答一覧モーダルに日時を足せば同等（現状は名前のみ） |
| 締切後のボタン無効化 | 共通ウィジェットに移植すれば同等 |
| 「全員回答済み」表示 | 同上 |

つまり**固有機能は無く、すべて移植可能**。残す理由は「共有リンクの着地先としての単純さ」だけ。

## 3. 選択肢の比較

| | 案A: 廃止して各ページにインライン統合 | 案B: 現状維持＋導線改善のみ | 案C: 併存（インライン化しつつ vote.html も残す） |
|---|---|---|---|
| 概要 | 投票UIを共通ウィジェット化し、ホーム・イベント詳細・日程一覧ポップアップに埋め込む。vote.html はリダイレクタ化→廃止 | vote.html を正とし、バッジ常時表示などの小改善だけ行う | 案Aを実施しつつ、vote.html も専用ページとして保守し続ける |
| ページ遷移 | **ゼロ**（見ている場所で回答完結） | 従来どおり遷移あり | 場所による |
| 共有リンク | 詳細ページ＋自動スクロールで代替 | 従来どおり | 従来どおり |
| 実装の重複 | **解消**（1ウィジェットに集約） | 3重実装のまま | ウィジェット＋vote.html の2重に戻る |
| 保守コスト | vote.js(329行)+vote.html+専用CSSを削減 | 現状のまま | **最大**（結局2系統を保守） |
| リスク | 旧リンク切れ（リダイレクタで回避可）／詳細ページの情報過多 | 導線の分裂が残る | 仕様差分が再発しやすい |

**評価**: 案Bは問題の根本（分裂と重複）を放置する。案Cは「せっかく統合したのに保守対象が増える」
自己矛盾があり、小規模サークル運用のこのサイトでは過剰。**案Aを推奨**する。

## 4. 推奨案（案A）の具体像

### 4.1 各ページの投票UIの姿

新規 `vote-widget.js` に共通ロジックを集約する（search.js と同じ発想。読み込み順:
`config.js → api.js → app.js → vote-widget.js → 各ページJS`）。

提供するもの:

| 関数 | 役割 |
|---|---|
| `voteEligibleMembers(members, event)` | 年度・Active・スタッフ除外の対象者算出（現3重実装を統合） |
| `renderVoteButtons(container, event, opts)` | 名前選択＋参加/不参加/未定ボタン＋自分の回答ハイライト |
| `renderVoteSummary(container, event, votes)` | 4カウント＋「全員回答済み」 |
| `openVoteListModal(event)` | ステータス別名前一覧（**回答日時つき**に強化） |

各ページの配置:

1. **ホーム** — 現行の「出欠の回答」一括回答を維持（既に理想形）。内部実装だけウィジェットに置き換え。
2. **イベント詳細 (event-series)** — 「参加状況」カード（event-series.js:617-624）に
   ウィジェットを埋め込み、**その場で回答できるようにする**。「回答する」リンクは削除。
   回答一覧モーダルは日時つきに強化して維持。ここが投票の「正式な置き場所」になる。
3. **日程一覧 (events)** — 概要ポップアップ（script.js:557-561）の「出欠を回答」ボタンを
   ウィジェット（3ボタン）の直接埋め込みに置き換え。名前未選択の端末では
   「名前を選択」プルダウンを同モーダル内に表示。
   行内バッジは `参加 n` → **`参加 n/12`（分母=対象者数）** にし、リンク先を
   `event-series.html?event=xxx&vote=1` に変更。**回答0件でも今後の日程なら常時表示**する
   （(c) の解消）。
4. **操作の作法を統一** — 全箇所「タップ即送信（楽観的更新）＋トースト＋失敗時ロールバック」
   （ホーム方式）に統一し、確認ダイアログは廃止。ワンタップで済む3値の選び直しは容易なので、
   確認を挟む価値よりテンポを優先する。

### 4.2 共有リンク運用の代替

「LINE に投票リンクを貼る」運用は `event-series.html?event=ev_xxx&vote=1` で代替する。
`vote=1` があれば参加状況カードへ自動スクロールし、名前未選択なら名前選択を強調表示する。
着地先がイベント詳細になることで、**回答のついでに持ち物・集合時間も確認できる**という副次効果があり、
むしろ運用上は改善になる。

### 4.3 移行ステップ

1. `vote-widget.js` 新設。home.js の一括回答を移植して動作確認（挙動は不変）。
2. event-series の参加状況カードにインライン投票を実装。回答一覧モーダルに日時を追加。
3. events 一覧: バッジの常時表示＋分母表示＋リンク先変更。概要ポップアップに3ボタン埋め込み。
4. **vote.html を数行のリダイレクタに置換**:
   `location.replace('event-series.html?event=' + id + '&vote=1')`。
   LINE のトーク履歴等に残る旧リンクを割らないため。vote.js・専用CSSはこの時点で削除。
5. 1〜2か月後（旧リンクの寿命が尽きた頃）に vote.html 自体を削除。
6. docs/01_sheets_schema.md に `EventVotes` シートを追記（今回の作業と独立にやるべき）。

## 5. 参加メンバーまわりの改善案（投票方法・保存・表示）

vote.html の存廃と独立に検討する価値のある改善。優先度順。

### 5.1 表示の改善（優先度: 高）

- **分母の常時表示**: 「参加 5」だけでは全員中どれだけ回答したか分からない。
  一覧バッジ・詳細サマリーとも「参加 5 / 対象 12（未回答 4）」の形に。
- **未回答者リマインドの個人化**: 名前選択済みの端末では、ホームの「要対応」に
  「あなたが未回答の日程が n 件」を出す。既存の `listVotes` ＋ localStorage の名前で実装でき、
  サーバー変更不要。
- **未回答者一覧のコピー**: 幹事がリマインドを打つとき用に、回答一覧モーダルに
  「未回答者をコピー」ボタン（`navigator.clipboard`）。「@田中 @佐藤 出欠お願いします」が3秒で作れる。

### 5.2 保存方式の拡張（優先度: 中）

- **一言メモ列の追加**: 現状3値では「参加（ただし遅れて）」「途中まで参加」が表現できず、
  結局 LINE で補足することになる。`EventVotes` に `note` 列を1本足し、
  投票ボタンの横に任意の一言入力（20字程度）を置く。upsert 形式のまま拡張可能で、GAS 側の変更も小さい。
- **回答締切の任意設定**: 現在は「イベント終了まで」変更可能だが、実務では
  「◯日前に人数確定したい」ことが多いはず。イベントに `VoteDeadline`（任意）を追加し、
  締切後は表示のみ・変更は管理者のみに。**運用で困っていなければ後回しでよい**。

### 5.3 本人性・なりすまし（優先度: 低 — 現状維持を推奨）

プルダウン自己申告＋端末記憶は性善説だが、①サイト自体がパスワードゲート内、
②全投票が監査ログに残る（gas/Code.gs:411）、③サークル規模では誤操作の方がなりすましより現実的、
という理由で**メンバー別PIN等の認証強化はやらない**ことを推奨。
代わりに誤操作対策として「**○○さんとして回答中**」の表示を投票ボタンの直上に常時出す
（共有PCで前の人の名前のまま押してしまう事故の抑止）。

### 5.4 API・実装の整理（優先度: 中）

- **`listAll` に votes を同梱**: ホームは現在 `listAll` → `listVotes` の2往復（home.js:57, 94）。
  GAS の `listAll` レスポンスに votes を含めれば1往復になり、一覧バッジ・詳細サマリーの
  初期表示も速くなる（`getEventVotes` の個別取得も不要に）。
- **対象者算出ロジックの一本化**: §4.1 のウィジェット化で自動的に解消。

### 5.5 やらないこと（過剰設計の回避）

- 投票履歴の全保存（追記型への変更）— 監査ログで十分。
- メンバー別ログイン/PIN — 上記 5.3 のとおり。
- 出欠の自動集計通知（メール/LINE Bot）— 現インフラ（静的サイト+GAS）に対して大掛かりすぎる。
  まず 5.1 の「コピー」ボタンで運用を軽くするのが先。
