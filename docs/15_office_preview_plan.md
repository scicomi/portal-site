# 15 Word・Excel・PowerPoint を、ダウンロードせずに開く(Office Online ビューア)計画

状態: **計画のみ(未実装)**。実装前に、人の了承を得る。

## 1. やりたいこと

アップロードしたファイルのうち、PDF は押すとブラウザ内で開くが、Word・Excel・PowerPoint は押すとダウンロードになる。これを、**押したら Microsoft の Office Online ビューアで開く**ようにする。

- 見た目は今までと変えない(「プレビュー」ボタンは足さない。リンクを押すと、今までと同じく新しいタブで開く。開く先が変わるだけ)
- 「Microsoft のサービスを使います」という断り書きは出さない(人が決めた)

## 2. 決まっていること(判断の記録)

人と話し合って決めた内容。後から経緯が分かるように残す。

| 項目 | 決定 | 理由 |
|---|---|---|
| 方式 | Office Online ビューア(`view.officeapps.live.com`) | 無料で、見た目の再現度が高い。ブラウザ内で変換する方式(mammoth.js など)は、図や書式が崩れる |
| ファイルへのログイン要求 | **今回はしない** | 下の §6 のとおり、リスクは認識したうえで、現状の仕組み(URL を知っていれば誰でも見られる)のままにする |
| 断り書き | 出さない | 人の判断 |

## 3. 現状の調査結果

### 3-1. ファイルの仕組み

- アップロード(`worker/src/files.js` の `uploadFile`)は、R2 にランダムなキーで保存し、`https://scicomi-portal.scicomi.workers.dev/files/<ランダム32文字>.<拡張子>` の URL を返す
- **URL の末尾に元の拡張子が付く**(`safeExt`。小文字化、英数字 8 文字まで)。ファイルの種類は、URL か `f.name` の拡張子で判定できる
- 閲覧(`serveFile`)はログイン不要。画像・PDF・動画・音声・テキストだけ `inline`、それ以外(Word など)は `attachment` で返す。これが「ダウンロードになる」原因
- `Cache-Control: public, max-age=31536000, immutable`、`X-Content-Type-Options: nosniff`

### 3-2. ファイルのリンクが作られている場所(全部で 6 か所)

Word などの書類を扱うのはイベント(と、ミーティング)とガイドだけ。実験の写真・パスワード一覧の写真は画像専用(`accept="image/*"`)なので対象外。

## 4. 実装の方針

### 4-1. 共通関数を `app.js` に 1 つ足す

```js
// ファイルを開くときの URL。Word・Excel・PowerPoint は Office Online ビューアで開く。それ以外は元の URL のまま。
function fileOpenUrl(url) { ... }
```

条件(すべて満たしたときだけ変換し、満たさなければ引数をそのまま返す。つまり失敗しても今までと同じ動きになる):

1. `url` が `http(s)://` で始まる
2. URL のパスの拡張子が `doc` `docx` `xls` `xlsx` `ppt` `pptx` のいずれか(大文字小文字は区別しない。クエリ・ハッシュは除く)
3. ホストが `localhost` / `127.0.0.1` / `[::1]` / プライベート IP でない(ローカルの開発 API の URL は、Microsoft から届かないので変換しない)
4. 自分の API のファイル(`CONFIG.API_URL` と同じオリジンの `/files/` 以下)であること。利用者が貼った外部のリンク(Teams、OneDrive など)は今まで通りそのまま開く

変換後:

```
https://view.officeapps.live.com/op/view.aspx?src=<encodeURIComponent(元の URL)>
```

`view.aspx`(全画面のビューア)を使う。`embed.aspx`(埋め込み用)は使わない。新しいタブで開く今のリンクの形を、そのまま保てるため。

### 4-2. 6 か所のリンクを、`fileOpenUrl` を通すように変える

`href="${escapeAttr(url)}"` を `href="${escapeAttr(fileOpenUrl(url))}"` にするだけ(ガイドは `a.href = fileOpenUrl(this.data.url)`)。`target="_blank" rel="noopener"` はそのまま。見た目・クラス・文言は変えない。

保存されるデータ(`Files` の `url` など)は**変えない**。変換は表示のたびに行うので、既存のファイルも、すべて自動で対象になる。

### 4-3. Worker は変えない

`serveFile` は変えない。`npm run deploy` は不要で、フロントの `git push` だけで反映される。

### 4-4. ドキュメントの更新

- `AI向けREADME.md` の §7 に、次を追記する: Word・Excel・PowerPoint は Office Online ビューアで開く(`app.js` の `fileOpenUrl`)。ファイルの URL が Microsoft に渡る。ローカルの開発 API では変換されない
- `README.md` に、ファイルの説明があれば合わせる(実装時に確認)

## 5. 動作の確認

### 5-1. ローカルでできること(`npx http-server . -p 8080 -c-1`)

⚠ `?api=` を付けずに開くと本番 API につながる(`AI向けREADME.md` §4)。確認は読み取りだけにして、保存・削除はしない。

- `fileOpenUrl` を、ブラウザの JS で直接呼んで、次の入力を確かめる
  - 本番の `/files/xxx.docx` → ビューアの URL に変わる
  - `.xlsx` `.pptx` `.doc` `.xls` `.ppt`、大文字の `.DOCX` → 変わる
  - `.pdf` `.png` → そのまま
  - 拡張子なし、`?x=1.docx` のように拡張子がクエリにある URL → そのまま
  - `http://127.0.0.1:8787/files/xxx.docx` → そのまま(ローカル API)
  - Teams などの外部 URL(`https://example.com/a.docx`)→ そのまま
  - 空文字・`null` → そのまま(例外を出さない)
- 6 か所の画面で、リンクの `href` が期待どおりか、DOM で確かめる(クリックはしない)

### 5-2. ローカルでできないこと(本番でしか確かめられない)

**ビューアが実際にファイルを表示できるかは、Microsoft のサーバーから届く URL でしか試せない**(`localhost` は届かない)。そのため、`git push` の後に本番で確かめる。

確かめる内容(**未検証**。下の §7 のリスク参照):

1. `attachment` で返す Word ファイルを、ビューアが読めるか
2. Excel・PowerPoint も同様に開けるか
3. 日本語のファイル名の書類でも開けるか(キーはランダムなので問題ないはず)
4. ファイルサイズの上限に引っかからないか(§7)

試験用には、**個人情報を含まないダミーの Word・Excel・PowerPoint**を用意して、イベントの関連ファイルに上げる(確認が済んだら、人の了承を得て削除する)。実際の名簿などは使わない。

## 6. 認識しているリスク(人が了承済みの内容)

詳細な議論は会話の記録によるが、要点を残す。

- ポータルのファイルは、URL を知っていれば**ログインなしで**誰でも見られる(推測は事実上不可能だが、URL が人から漏れると止められない。退部者・卒業生が持つ URL も、パスワードを変えても無効にならない)。個人情報(学籍番号・氏名・教職員の電話番号)を含む書類がすでに上がっている
- Office Online ビューアを使うと、ファイルの URL が Microsoft に渡り、Microsoft のサーバーがファイルを取得して処理する。大学と Microsoft の契約(Teams が受けているもの)の外で、個人情報が処理されることになる。実害が出る可能性は低いが、大学や本人に説明を求められうる点は残る
- 今回は、ファイルの閲覧にログインを要求する対策を**見送る**(人の判断)。後からやる場合は、`serveFile` を認証付きにし、画像・リンクの読み込み方を直す必要がある(影響範囲が広いので、別の計画にする)
- 個人情報入りの書類をポータルに上げるかどうか、大学の規程上問題ないかは、顧問・学生課への確認事項(AI には判断できない)

## 7. 実装上の注意・不確かな点

Office Online ビューアの仕様は公式に細かく保証されたものではなく、**以下は未検証**。実装後に本番で確かめ、結果をこの文書に書き足す。

| 項目 | 内容 | 対応 |
|---|---|---|
| ファイルサイズ | ビューアには種類ごとの上限があるとされる(目安: Word 10MB、Excel 5MB 前後、PowerPoint 数十MB。正確な値は未確認)。ポータルの上限は 10MB(設定で 1〜20MB) | 開けないときは、ビューアの画面にエラーが出る。今回は特別な処理をしない |
| `attachment` で返すファイル | ビューアが問題なく読むかは未確認 | 開けなければ、`serveFile` の返し方の調整が要る(その場合は Worker の変更と `npm run deploy` が加わる。人の了承を得る) |
| 仕様変更 | `view.officeapps.live.com` は Microsoft の都合で変わりうる(過去に配布終了の話が出たことはないが、保証はない) | 開けなくなったら、`fileOpenUrl` を元の URL を返すだけに戻せば、従来どおりダウンロードになる(1 か所の修正で戻せる) |
| ブラウザの履歴・ネットワークログ | リンクの URL に、ファイルの URL が入る | 変更前から、ファイルの URL 自体は同じ扱い |
| パスワード保護された書類 | ビューアは開けない | 利用者に、ダウンロードで開いてもらう(ビューアの画面にはダウンロードのリンクがある) |
| 古い Office 形式(`.doc` `.xls` `.ppt`) | 対応しているとされるが未確認 | 本番の確認で試す |

## 8. 戻し方
